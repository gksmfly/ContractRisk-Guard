# 논문 실험 계획 v3 (2026-09-28)

KAICTS 2026 게재본의 확장판을 위한 계획이다. 7월에 세운 계획(이하 "옛 계획")은 라벨 체계가
**해지/책임제한 + 위험도 3단계 + 위험 패턴**이던 때의 것이다. 지금 운영과 학습은
**약관규제법 제6~14조 multi-label**이고 위험도 헤드는 없다. 그래서 옛 계획의 상당 부분은
"안 했다"가 아니라 **대상이 없어졌다.** 이 문서는 무엇을 주장할지부터 다시 정하고, 주장마다
이미 가진 근거와 새로 재야 할 것을 나눈다.

수치 인용의 단일 출처는 [`reported_numbers.md`](reported_numbers.md)다. 이 문서의 수치는 그
파일과 `data/eval/*.json`에서 확인한 값만 옮겼고, **전부 서버 복구 후 재현 전의 값**이다(§1).

## 1. 전제와 제약

1. **사람 라벨 없음.** 변호사 등 전문가 라벨링은 불가하다(09-06 결정, 09-28 재확인).
   - FTC 의결서 `근거_법령`은 **규제기관이 사건마다 내린 전문가 판정**이다. 이것을 전문가 라벨로 프레이밍한다
   - 한계: 위반 사건만 있다(음성이 없다). 조항과 근거의 귀속이 명확한 층은 255건뿐이다([`project_gold_ceiling`] 09-19 전수 조사)
   - 음성은 "정부 발행 표준계약서는 적법하다"는 **출처 준거**로만 만든다. 이 가정 자체가 흔들리는 폭이 오경보 2.3~12.1% 구간이다
2. **gold 천장 255.** 조 F1 +3%p를 가리려면 n≈3,400이 필요하다. 조 F1로 우열을 주장하는 실험은 설계하지 않는다
3. **서버 침해(09-22 03:23부터 root).** `dual_channel_recall_mini.json`, `style_transfer_fpr.json`은 그 뒤에 생성됐다. 09-02에 미확인 로그인 기록도 있다. **Phase 0 재현 전에는 어떤 수치도 논문에 옮기지 않는다**
4. **방향 비대칭.** 재측정 10건 중 모델에 유리한 정정이 7건이었다(`reported_numbers.md` §7). 새 실험도 **판정 규칙을 실행 전에 이 문서에 적는다**

## 3. 옛 계획 대조

| 옛 항목 | 처리 | 이유 / 대체 |
|---|---|---|
| 1-1 Ablation (필터 없음·무작위·FB-Check로 v2를 각각 학습) | **대체 + 유지** | 하류 학습 비교는 gold 255에서 판정되기 어렵다 → 주 판정은 **라벨 수준**(E1)으로 옮기고, 하류는 E8로 사전 등록 |
| 1-2 Baseline 비교 표 | **수치 폐기, 실험은 재설계** | 표의 75.2~83.5%는 측정값이 아니다. CleanLab·모델 신뢰도 임계값은 API 없이 가능(E3). self-consistency는 API 필요(E11, 선택) |
| 1-3 Held-out (FTC 100 + human 50~100) | **부분 완료, human 폐기** | FTC gold clean 255(학습 문서 배제)가 held-out이다. human gold는 만들지 않는다. "패턴매칭 0.97"은 라벨 체계가 없어져 해당 없음 |
| 1-4 Error analysis (해지/책임제한·위험도·패턴별) | **축 교체** | 조별 F1, NOISE 사유·방향별, 조항 잘림, 문체 교락은 했다. 조 간 혼동 행렬만 새로(E4) |
| 2-1 Prompt sensitivity (5~10 변형, kappa) | **재해석** | 4 변형(A/A'/B/C, 100건)을 했는데, **같은 프롬프트 재실행(A vs A')이 유의하게 달랐다**(p=0.049, 9건 변동). temperature 0의 비결정성이 프롬프트 차이만큼 크다는 게 발견이다. "FB-Check가 민감도를 완화한다"는 API가 필요해 선택(E12) |
| 2-2 Calibration (GPT-4o ECE 0.18→0.07) | **수치 폐기, 대상 교체** | GPT-4o 신뢰도는 저장된 적이 없다. 기존 calibration은 폐기된 v4 모델 값이다(ECE 0.289). `article_v2` sigmoid 보정을 새로 잰다(E7) |
| 2-3 ICL vs Fine-tuning | **대부분 있음** | gpt-4o 프롬프트 · teacher(옛 gold 327 기준 — clean 255로 재채점 필요) · 인코더 · sLLM LoRA 3종. few-shot만 없다(API) |
| 2-4 Multi-LLM labeler (GPT/Claude/Gemini/…) | **로컬 오픈모델로 대체** | API 없이 EXAONE·Qwen·Llama로 라벨링 → FTC 대비 F1과 라벨러 간 kappa(E9). FB-Check 일반화(C1'')까지 한 번에 본다 |
| 5. 실험 설계 "인간 1,000 vs 부트스트래핑 10,000" | **폐기** | 사람 라벨 없음 |
| 5. 모델 붕괴 방지 모니터링 | **재정의 후 구현됨** | 라벨에 모델 출력이 안 들어가 붕괴 조건이 없다. 실제 위험(라벨러 변경·누적 하락)은 `backend/training/retrain.py`가 막는다 |

### Phase 1 — 기존 데이터, API 0

**E1. 라벨 수준 ablation** ← **v3: E8로 흡수. 독립 실험 폐지, 부록으로 강등**

- E8이 동일한 질문을 3 seed·페어드 부트스트랩·A arm 포함으로 더 엄밀하게 다룬다
- E1 결과(`data/eval/label_ablation.json`)는 E8과 일관성 확인 후 부록에 표로만 수록
- forward_nonempty C=46.7% > B_p975=44.3%, Δ=+3.2%p, perm_p=0.000 (완료, `reported_numbers.md` 참조)

**E2. FB-Check 구성 요소 ablation**

- 같은 모집단에서 제거 규칙을 하나씩 켠다: (a) `snippet_not_found`만 (b) `article_mismatch`만 (c) `label_mismatch`만 (d) 전부(=현행)
- 각 규칙의 제거 수에 맞춘 무작위 제거와 비교(E1과 같은 순열 틀)
- **탐색 표기:** "forward=High는 살린다"는 규칙은 이 데이터에서 찾은 것이라 **확증 주장 금지**. 표에 탐색으로 표기하고, E9의 다른 라벨러에서 같은 방향이 나오면 그때 재현으로 적는다
- 산출: E1 스크립트의 옵션. 비용 CPU

**E3. 기존 필터 방법 비교: CleanLab · 모델 신뢰도 임계값**

- 준비: `ftc_case` 레코드로 **문서 단위 5-fold** 인코더 학습 → out-of-fold 확률(학습 설정은 `article_v2`와 같게)
- CleanLab: `cleanlab.multilabel_classification.filter.find_label_issues`로 이슈 순위 → **FB-Check와 같은 수(832)** 제거
- 신뢰도 임계값: 라벨된 조의 OOF 확률 평균이 낮은 순으로 832건 제거
- 판정: 각 방법이 남긴 1,473건의 FTC 대비 F1을 E1의 B 분포와, 그리고 FB-Check와 페어드 비교(겹치는 레코드가 많아 부트스트랩은 레코드 단위)
- 주의: CleanLab은 **모델이 라벨을 고르는** 방법이라, 그 모델을 같은 라벨로 학습했다는 순환이 있다. 표에 명시한다
- 의존성: `cleanlab` 미설치 → `requirements-dev.txt`에 추가 필요
- 비용: GPU 5회 학습(1회 수십 분 규모 — 첫 fold로 실측 후 기록)

**E4. 조 간 혼동 분석**

- gold 255에서 예측 조 vs 정답 조 혼동 행렬. 제6조(일반원칙)로의 흡수, 제8조 방향성(갑→을) 오류가 몇 건인지
- C7에서 사람이 판정한 3개 유형(위약금·양도금지·자동갱신)은 **판정자가 비전문가**이므로 사례로만 인용한다
- 비용: GPU 추론 1회

**E5. 오경보 하한 2.3% 재계산** ← 현재 근거가 무너져 있다

- 분모를 철회된 613이 아니라 온전 지층 **908**로. 모델 플래그 ∧ GPT forward 빈 배열 = 순수 오경보
- 191건 배타 분류 중 재현 불가인 "헤딩아님 74"는 쓰지 않는다
- 판정 없음(값 보고). 결과로 `reported_numbers.md` §2의 구간을 교체한다
- 비용: GPU 추론 1회(908건)

**E6. 조 F1 49.1% vs 상수 기준선** ← **v3: 강등. sanity check로만**

- 완료: CI [6.1, 21.2]%p, 0 불포함 → 논문 확정 (`reported_numbers.md` §1)
- **프레이밍 변경:** "상수 기준선을 이겼다"가 핵심 결과가 아니다. 표에서 sanity check 행으로만 수록
- 선행 연구(ICAIL 2025 등)는 LLM 직접 추론 대 파인튜닝 비교가 표준. E_teacher가 이를 채운다

**E7. `article_v2` 확률 보정** ← **v3: 부록으로 강등**

- 완료: macro ECE=0.1178 (`reported_numbers.md`)
- 비교 대상(다른 arm ECE) 없이 단독 수치만으로는 해석 불가 → 부록으로만 수록
- 비용 추가 없음

### Phase 2 — GPU, 새 학습

**E8. 하류 학습 ablation (사전 등록, 미판정 예상)** ← **v3: E1 흡수, 핵심 ablation**

- 팔: A 필터 없음(forward, 4465건) · C FB-Check(현행 agreed CLEAN, 3352건) · B 무작위(A에서 3352건)
- 각 팔 3시드. 학습 설정은 `article_v2`. 음성 홀드아웃 `negative_holdout_docs.json` 고정
- 지표: gold 조항 재현(페어드 부트스트랩), 홀드아웃 오경보
- **사전 MDE:** ±4.3%p. CI 포함 0이면 "미판정, MDE ±4%p" 보고(규칙 8)
- 판정: C−A와 C−B 각각
- **상태: 실행 중** (Arm A 3/3 완료, Arm B 3/3 완료, Arm C 2/3 진행 중, 2026-09-28)
- 비용: 9회 학습 (완료 임박)

**E9. 로컬 오픈모델 라벨러 — FB-Check 일반화** ← C1'', **v3: 검증 기준 교체**

- 라벨러: EXAONE-3.5-7.8B, Qwen2.5-14B(4bit), Llama-3.1-8B. 프롬프트: fwd-v5 / ver-v5
- 모집단: FTC 2,305건
- **질문 1 (유지):** 각 라벨러의 forward 라벨 **FTC gold 대비 F1** (gpt-4o와 비교)
- **질문 2 (유지):** 각 라벨러로 FB-Check 시 CLEAN > 무작위 제거가 재현되는가 (E1 틀, FTC gold 기준)
- **질문 3 (보조만):** 라벨러 간 Fleiss kappa — 일관성 지표. 높은 kappa ≠ 정확도. 순환 위험(같은 프롬프트 → 오류 상관) 표에 명시
- **v3 변경:** "agreed 교집합이 GPT CLEAN 라벨과 일치하는지" 검증 **폐기** (순환). FTC gold가 유일한 외부 기준
- 파일럿 결과: Qwen 1%/4.65s, Llama 8%/9.14s, EXAONE 15%/21.35s
- **상태: 실행 중** (Qwen [650/2305], Llama 진행 중, EXAONE 예약됨, 2026-09-28)
- 라이선스: EXAONE NC(연구 OK). 제품 사용 시 Qwen(Apache 2.0)만

## 6. 한계 (논문에 그대로 쓴다)

- 사람 전문가 라벨이 없다. FTC 의결서는 위반 사건만 담고, 음성은 출처 가정에 기댄다
- 오경보는 구간으로만 보고한다. 하한과 상한의 차이는 "표준계약서는 적법하다"는 가정의 불확실성이고, 이 연구에서 좁히지 않는다
- 조 F1은 gold 255로 판정할 수 없다(필요 n≈3,400). 모델 개선 주장은 조항 단위에 한정한다
- 실제 기업 약관 99건에서의 행동 변화(지목률 39.4→28.3%)는 정답이 없어 채점하지 못했다
- 라벨러가 gpt-4o 한 종류다(E9가 부분적으로 보완)
