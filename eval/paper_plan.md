실험을 다시 검증한 결과**와 외부에서 제안받은 실험 목록(§3)을 이 프로젝트 조건에 맞춰 걸러낸
결과를 담는다.

수치 인용의 단일 출처는 [`reported_numbers.md`](reported_numbers.md)다. 이 문서의 수치는 전부
`data/eval/*.json`에서 옮겼고 스크립트 경로를 같이 적었다.

## 1. 전제와 제약

1. **사람 라벨 없음.** 전문가 라벨링은 불가하다(09-06 결정, 09-28 재확인). FTC 의결서 `근거_법령`을
   규제기관의 전문가 판정으로 쓰고, 음성은 "정부 표준계약서는 적법"이라는 출처 준거로만 만든다
2. **gold 천장 255.** 조 F1 +3%p를 가리려면 n≈3,400이 필요하다. 조 F1 우열을 주장하는 실험은 설계하지 않는다
3. **사건 단위 준거의 교락 (v4 신규).** E1·E2·E3·E9가 쓰는 2,305건 모집단에서는 근거_법령을 사건의
   모든 조항에 복제해 붙인다. 이 모집단의 최적 상수(6개 조 고정)가 **F1 54.4%로 GPT(37.3%)를 포함한
   모든 라벨러를 이긴다.** 그래서 절대 F1은 해석하지 않고 상대 비교만 하며, 필터 비교에는 **문서 층화
   무작위 기준선**(같은 문서 안에서만 섞기)을 함께 낸다. 층화 전 이득의 1/4~4/5가 문서 구성 효과였다
4. **서버 침해(09-22).** E0 재현이 전부 일치해 결과 파일 변조 가능성은 낮다고 본다. 서버 보안 조치는 별개 문제
5. **방향 비대칭.** 판정 규칙은 실행 전에 이 문서에 적는다. v4의 정정 11건은 **불리 9 / 유리 1 / 중립 1**이다.
   불리: E8 철회 · CleanLab 동률 · C5 수정 · E_base 수정 · E1·E9·교차검증의 층화 축소 · AI Hub 실제 학습 수 맞춤 · E3 신뢰도 임계값 우위 소멸(OOF 재학습). 유리: E1 agreed 전사 오류 정정.
   중립: AI Hub 누수. v3까지의 재측정(유리 7 / 불리 1)과 방향이 반대다 — 이번엔 "높아 보이는 수치"를 추적했다

## 3. 외부 제안 실험 대조 — 채택·제외와 이유

| 제안 | 처리 | 결과 위치 |
|---|---|---|
| 계약서(문서) 단위 분할 | 이미 함 — `split_by_document()`가 문서 간 중복 55.4%까지 제거. 제안보다 엄격 | 학습 전 경로 |
| 필터 전체 vs 필터 후 vs **같은 수 무작위 제거** | E1(라벨 수준)·E8b(하류). v4에서 기준선 표본 크기 버그 수정 + 문서 층화 추가 | §4 P1-1, P1-2 |

### 3-2. 제외 — 이유

| 제안 | 제외 이유 |
|---|---|
| **Step 0: gold 300~500건 2인 라벨링 + Cohen's κ** | 사람 라벨은 이 프로젝트에서 만들 수 없다(09-06·09-28 결정). 외부 준거는 FTC 의결서(규제기관 판정)와 출처 준거뿐이다. 한계 절에 "평가자 간 일치도 미측정"으로 적는다 |

| "Medium 헤드 정밀도 12~13%, 소스 간 2.6배"를 부록에 | **그 수치는 08-17에 틀린 것으로 정정됐다**(고친 분할에서 Medium precision 61.9%). 인용 금지. `reported_numbers.md`의 같은 문장도 v4에서 가설로 강등 |

### P1-1 — E1 라벨 수준 ablation (재측정)

`eval/label/label_ablation.py` → `data/eval/label/label_ablation.json`. 모집단 ftc_case 2,305 (CLEAN 1,473 / NOISE 832).

**고친 것:** 옛 무작위 기준선은 빈 라벨을 이미 뺀 배열에서 "빈 포함 레코드 수(1,473)"만큼 뽑았다.
C 쪽(1,158)과 표본 크기가 달라 무작위 분포가 좁아지고 → 통과 쪽으로 기울었다.
**`reported_numbers.md`의 agreed "−1.4%p 미판정"은 agreed C를 forward용 기준선(44.3%)과 비교한 전사 오류**였다.

| 라벨 | C (FB-Check) | 무작위 B p97.5 | Δ(C−B) | 문서 층화 Δ | 판정 |
|---|---|---|---|---|---|
| forward | 46.7% (n=1,158) | 44.5% | +3.2%p (p<0.001) | **+2.4%p (p<0.001)** | 질의 효과 |
| agreed | 42.8% (n=1,150) | 42.7% | +1.1%p (p=0.020) | **+0.8%p (p=0.009)** | 질의 효과 |

- 헤드라인은 **층화 값**이다. 층화 전 이득의 약 1/4이 "쉬운 문서의 조항을 더 남긴" 효과였다
- 학습셋에 들어가는 라벨은 agreed다. agreed 이득은 작지만(+0.8%p) 유의하다

## 7. 배포 모델 교체 검토 — KoELECTRA article_v2 → KLUE-RoBERTa (사전 등록, 2026-10-05)

**동기:** paraphrase 위반 조항에서 article_v2 재현 −20.7%p, RoBERTa는 유지(P2-⑤). 같은 데이터에서 RoBERTa 조 F1 +3.8%p 경계(P1-2).

**후보:** `models/_e8_RB_s42` — 3시드 중 **dev** 제6조 제외 macro 최고(0.802 / 0.787 / 0.777). gold로 고르지 않는다.
나머지 두 시드는 안정성 확인용으로 같이 잰다.
**대조군:** `models/_e8_C_s{dev 최고}` — KoELECTRA를 현행 데이터로 학습한 것. article_v2는 **옛 데이터 963건**으로 학습돼
있어 교체는 "데이터 + 백본"이 함께 바뀐다. C로 두 효과를 나눈다(C − article_v2 = 데이터, RB − C = 백본).

**판정 규칙 (이 순서, 결과를 보기 전에 적음):**

| 단계 | 축 | 기각 조건 |
|---|---|---|
| ① 무해 (기존 `retrain.py` 규칙 그대로) | gold 255 조항 재현 · 홀드아웃 12문서 오경보, 각자 배포 임계값 | 재현 차 CI 상한 < 0 또는 오경보 차 CI 하한 > 0 → **기각** |
| ② 교체 이유 (paraphrase) | 변형 위반 조항 재현의 하락폭: (후보 하락) − (현행 하락) | 후보 하락이 현행보다 **유의하게 작지 않으면 교체 이유 없음** → 보류 |
| ③ 부작용 (오경보 계열, 각 5%p = 학습 잡음 바닥) | paraphrase 표준계약서 오경보 · B4 문체 변환 오경보(273건) · 온전 지층 908 오경보 | 어느 하나라도 후보가 **5%p 넘게 높고 CI 하한 > 0** → 보류 |
| ④ 행동 변화 (판정 아님, 보고) | 실제 기업 약관 10개 지목률 | 지목률이 ±10%p 넘게 움직이면 경고 |
| ⑤ 서빙 | 토크나이저 호환(판정 경로 `ElectraTokenizerFast` 고정) · 지연·메모리 · 스모크 · pytest | 하나라도 실패하면 코드 수정 후 재확인 |

## 7-2. 말투 편향 줄이기 (사전 등록, 2026-10-05)

**문제:** 학습 데이터에서 위반 = 공정위 사건의 **회사 약관 말투**, 비위반 = 정부 표준계약서의 **공문서 말투**다. 모델이 내용 대신 말투를
단서로 쓸 수 있다. B4(공정한 조항을 회사 약관 말투로 바꾸면 오경보 KoELECTRA 2.6→5.9%, RoBERTa 3.7→13.2%)가 그 증거다.

**방법 — 말투를 뒤집은 사본을 학습에 더한다(반사실 증강, API 0):**
- 바꿔 쓰는 모델: Qwen2.5-14B(로컬). 뜻·당사자·숫자·조건은 유지하고 말투만 바꾼다. 자동 검사(숫자 보존·길이 0.6~1.6·실제로 바뀜) 통과분만 쓴다
- 재료는 **학습 후보에서만**: 고정 홀드아웃 12문서 제외, gold 문서는 학습기가 문서 단위로 다시 뺀다. 사본은 원본과 같은 문서 묶음에 둬 dev 누수를 막는다

| 팔 | 학습 데이터 | 백본 |
|---|---|---|
| C / RB (기존) | clean.jsonl (agreed) | KoELECTRA / RoBERTa |
| **KSN / RSN** | + 공정한 표준계약서 1,374건을 **회사 약관 말투**로 바꾼 사본 (라벨 = 위반 없음) | KoELECTRA / RoBERTa |
| **KSS / RSS** | 위 + 위반 공정위 조항 1,206건을 **표준계약서 공문서 말투**로 바꾼 사본 (라벨 = 원본 조 그대로) | KoELECTRA / RoBERTa |

각 3시드, 설정은 C와 같다. 비교는 같은 백본의 기존 팔과 한다.

**판정 (결과 보기 전에 적음):**
1. **주 지표 — 말투 오경보:** B4 273건(GPT-4o-mini가 회사 약관 말투로 바꾼 공정한 표준계약서). 바꿔 쓴 모델이 학습 증강(Qwen)과 달라 "증강 모델의 버릇을 외운 효과"가 섞이지 않는다.
   증강 팔 − 기존 팔의 차가 **학습 변동 포함 CI로 0 미만**이면 "말투 편향 감소"

### 7-4. GPT 반복 실행 — GPT 우위의 실행 변동 확인 (사전 등록, 2026-10-06)

**왜:** E_teacher의 "GPT가 조 F1 4~7%p 앞선다"는 GPT 실행 1~2번에 기댄다. temperature 0에서도 실행마다 약 9%가 달라진다(A vs A').
재현 맞춤 차의 CI 하한이 +0.2%p로 0에 붙어 있어 실행 변동을 넣으면 사라질 수 있다.

**설계:** gpt-4o(명시 지정, `.env` 기본값 무시) · forward 프롬프트 fwd-v5 · temperature 0 · **5회 독립 실행**.
대상 gold clean 255 + 홀드아웃 300(조항 단위 오경보용). 비용 약 15달러(승인 10-06).

**판정:** 각 실행에서 (GPT − article_v2 배포) 조 F1 차와 (GPT − article_v2 재현 맞춤) 조 F1 차를 구하고,
5회 평균 차의 95% CI = 평균 ± 1.96·√(문서 군집 부트스트랩 분산 + 실행 간 분산/5).
CI 하한 > 0 이면 "GPT 우위 확인", 아니면 "실행 변동을 넣으면 미판정". 조항 단위 재현·오경보도 같은 방식으로 보고.

- 합집합 − FB-Check +2.1%p [+0.9, +3.4]는 남긴 수·문서 구성이 달라 판정에 쓰지 않는다(사전 등록대로)

### 7-6. FB-Check 향상 — 탐색 절반 / 확인 절반 (사전 등록, 2026-10-07 — 결과를 보기 전에 적음)

**문제:** 새로 라벨할 공정위 데이터가 없다. 같은 2,305건에서 방법을 고르고 판정까지 하면 사후 선택이다.
**설계:** 근거 있는 공정위 문서를 `random.Random(20261007)`로 **반씩 나눈다**(문서 단위). 앞 절반(탐색)에서만 후보를 비교·선택하고,
**선택한 방법 하나만** 뒤 절반(확인)에서 판정한다. 확인 절반은 선택이 끝날 때까지 채점하지 않는다.

**후보 (전부 API 0):**
| 후보 | 규칙 | 근거 |
|---|---|---|
| MV-Q | FB-Check CLEAN ∧ Qwen 재판정 CLEAN | LLM 앙상블 판정 (Nahum et al., EMNLP 2025). ⚠ §11에서 전체 데이터로 이미 본 방향이다 |
| MV-L | FB-Check CLEAN ∧ Llama 재판정 CLEAN | 같은 근거 |
| MV-QL | FB-Check CLEAN ∧ (Qwen 또는 Llama 중 하나 이상 CLEAN) | 검증자 다수결 완화형 |
| NB | FB-Check CLEAN ∧ 이웃 합의 점수 상위 (임베딩 kNN, 같은 문서 제외, k=10, 이웃의 forward 조 집합과 Jaccard 평균) — 하위 1/3 제거 | SimiFeat (Zhu et al., ICML 2022). 학습 없는 이웃 합의. **아직 결과를 본 적 없음** |

**판정 지표 (수와 무관, §7-5와 같은 틀):** FB-Check CLEAN 안에서 후보가 남긴 것 vs 버린 것의 F1, **문서 층화 순열**.
- 탐색 절반: 문서 층화 이득이 가장 큰 후보 하나를 고른다(동률이면 남기는 수가 많은 쪽)
- 확인 절반: 그 후보의 문서 층화 이득 > 0 이고 p < 0.05 → **"FB-Check 향상 확인"**. 아니면 미판정
- 보고만: 확인 절반에서의 나머지 후보 값(선택에 쓰지 않음), 남는 레코드 수

**한계:** MV 계열은 §11에서 전체 데이터 결과를 이미 봤다(확인 절반도 포함돼 있었다). 그래서 MV가 선택되면 확인 절반 결과도 "완전히 새 데이터"는 아니다 — 그대로 밝힌다.
NB는 결과를 본 적이 없어 이 설계로 공정하게 확인된다.

**결과 (10-07, `eval/label/fbcheck_plus.py` → `data/eval/label/fbcheck_plus.json`) — FB-Check 향상 확인 (MV-Q)**

문서 421개씩 탐색 1,173건 / 확인 1,132건. NB 컷(이웃 합의 0.45)은 탐색 절반에서만 정했다. 수치는 FB-Check CLEAN 안에서 후보가 남긴 것 vs 버린 것의 **문서 층화 이득**.

| 후보 | 탐색 절반 | **확인 절반** | 확인 절반 남긴 / 버린 F1 | 버리는 비율 |
|---|---|---|---|---|
| **MV-Q (선택)** | +4.13%p (p<0.001) | **+1.42%p (p=0.017) → 확인** | 50.0% / 43.2% | 49% |
| MV-L | −0.35%p | +0.32%p (p=0.35) | 49.6% / 45.4% | 51% |

- ⚠ MV-Q 방향은 §11에서 전체 데이터(확인 절반 포함)로 이미 봤다. 확인 절반 결과도 완전히 새 데이터의 확인은 아니다
- **NB(이웃 합의, SimiFeat식)는 결과를 본 적 없는 방법인데 탐색·확인 두 절반 모두에서 독립적으로 유의**했다. 사전 판정 대상(선택된 후보)은 아니므로 "보고" 지위지만, 근거의 깨끗함은 MV-Q보다 낫다.
  LLM 재판정과 원리가 다른(의미 이웃의 라벨 합의) 신호라 보완 가능성이 있다
- 비용: MV-Q는 CLEAN의 약 절반을 버린다(로컬 Qwen 재판정 1회 추가, API 0). NB는 1/3을 버리고 임베딩만 필요하다
- 하류 학습 효과는 재지 않았다(평가셋 한계로 판정이 어렵다 — §4 P1-2)

### 7-7. 다중 검증자 + 이웃 합의 결합 — 탐색 (2026-10-07, 계산 전에 적음)

§7-6에 없던 조합이라 **탐색**이다(두 구성요소의 확인 절반 값을 이미 봤다). 규칙은 계산 전에 고정한다.
- 결합 MV-Q∧NB: FB-Check CLEAN ∧ Qwen 재판정 CLEAN ∧ 이웃 합의 > 0.45(§7-6에서 탐색 절반으로 정한 컷 그대로)
- **주 질문(수와 무관):** MV-Q가 남긴 것 안에서 NB가 남긴 것 vs 버린 것, 문서 층화 이득. 탐색·확인 절반 각각과 전체에서 보고
- 보고: 반대 방향(NB가 남긴 것 안에서 MV-Q), FB-Check CLEAN 안에서 결합이 남긴 것 vs 버린 것, 남는 수
- 해석: 주 질문이 두 절반 모두에서 이득 > 0, p < 0.05 이면 "두 신호가 서로 보완한다(탐색)"

**결과 (10-07, `data/eval/label/fbcheck_plus_combo.json`) — 보완 미확인 (탐색)**

| 질문 (문서 층화 이득) | 탐색 절반 | 확인 절반 | 전체 |
|---|---|---|---|
| ★ MV-Q가 남긴 것 안에서 NB | −0.10%p (p=0.59) | +0.84%p (p=0.04) | +0.37%p (p=0.13) |
| 역: NB가 남긴 것 안에서 MV-Q | +3.78%p (p<0.001) | +1.45%p (p=0.01) | +2.63%p (p<0.001) |

- **NB의 정보는 대부분 MV-Q(Qwen 재판정)에 이미 들어 있다.** 반대로 MV-Q는 NB가 못 잡는 오류를 두 절반 모두에서 추가로 잡는다
- 결합은 데이터 손실(64% 제거)에 비해 추가 이득이 작다 → **둘 중 하나만 쓴다.** 라벨 품질 우선이면 MV-Q, 비용·데이터 보존 우선이면 NB

### 7-8. AI Hub 외부 대형 평가 — 라벨 필터가 학습 모델을 좋게 하는가 (사전 등록, 2026-10-07 — 결과를 보기 전에 적음)

**왜:** gold 255로는 하류 학습 차이를 4~7%p 아래로 못 본다. AI Hub에서 우리 데이터와 겹치지 않는 위반 2,575 · 공정 6,097건(§24에서 정의·누수 확인)을 외부 평가셋으로 쓴다.

**학습 팔 (전부 KoELECTRA, C와 같은 설정, 시드 42·7·123):**
| 팔 | 학습 데이터 | 라벨 |
|---|---|---|
| A | FB-Check CLEAN ∪ NOISE (필터 없음) | forward |
| B | A에서 C와 같은 수 무작위 | forward |
| D | FB-Check CLEAN | forward |
| C | FB-Check CLEAN | agreed (현행) |

**지표:** 주 지표는 **AUROC**(AI Hub 위반 vs 공정, 순위 점수 r = max(p/thr), 동작점 무관). 보조: 재현 80%에서의 오경보, 조문 1개짜리 위반 2,287건의 조 F1(배포 임계값).

**판정 (각각 CI 하한 > 0 이면 "개선"):**
1. **D − B** — 같은 수·같은 라벨 소스에서 FB-Check 필터가 무작위보다 학습 모델을 좋게 하는가
2. **MV − RMV** — 제안 방법이 같은 수 무작위 제거보다 나은가
3. **MV − C** — 제안 방법이 현행 FB-Check보다 나은가
- 보고만: C − A, CL − D, 조 F1, 재현 80% 오경보, 가짜 처치 대조(B와 A 차이의 시드 분산)

**한계(미리 적음):** AI Hub 조문은 공정위보다 관련 조문을 조금 더 붙인다(§24) → 조 F1 절대값은 낮다. AI Hub 공정 조항은 우리 음성(표준계약서)과 분포가 다르다 → 절대 오경보 값보다 팔 간 차이로 읽는다.

AI Hub는 조항마다 전문가가 조문을 단 정답이다(공정위와 주 조문 94.6% 일치, §24). 여기서 FB-Check 자체를 처음으로 시험한다.

**대상:** AI Hub 사용 가능 위반 **2,575건 전부** + 공정 조항 **2,575건**(6,097건 중 `random.Random(20261008)` 무작위). 1,500자 초과 제외.
**FB-Check (운영과 같은 프롬프트·규칙, 모델만 Qwen2.5-14B 4bit):** forward(조항 전문) → 근거 문구 원문 존재 검사(`check_snippet_exists`) →
verify(조가 있으면 근거 문구만, 없으면 조항 전문) → 등급 불일치 NOISE · 위험인데 조 교집합 없음 NOISE · 나머지 CLEAN. greedy.
**정답:** 위반 조항 = AI Hub 조문(제6~14조), 공정 조항 = 빈 집합.

**주 판정:** forward 라벨이 비어 있지 않은 레코드에서, 정답 대비 건별 F1(공정 조항에 붙은 라벨은 0점).
FB-Check가 남긴 것(CLEAN)의 평균 F1 vs **같은 수를 레코드 수준에서 무작위로 남긴 것**(10,000회).
**이득 > 0 이고 순열 p < 0.05 → "FB-Check 효과 확인(조항 단위 전문가 정답, Qwen)"**. 아니면 미판정 + MDE.

**보고:** ① 공정 조항에 붙은 잘못된 위반 라벨 중 FB-Check가 NOISE로 걸러낸 비율 vs 무작위 기대 · ② 위반 조항만의 F1 이득 · ③ 사유별(근거 없음·등급 불일치·조 불일치)
· ④ gold §25 방식(거른 라벨을 빈 예측으로 셈)의 필터 없음 대비 차 · ⑤ 파싱 실패 수.
**한계:** 검증자가 GPT가 아니라 Qwen이다 — 효과가 보이면 GPT로 확정한다(비용 승인 필요).

**실행 조건 수정 (2026-10-08, 결과 판정 전):** 첫 56건(짧은 조항부터 처리)에서 파싱 실패가 26.8%였다. 원인은
Qwen이 앞뒤가 잘린 조각 조항에 JSON 대신 줄글로 답한 것이다(묶음 처리 버그 아님 — 8건 재생성으로 확인).

**사후 추가 (2026-10-09): FB-Check를 예측기로 쓰면? — 쓰지 않는다.** 같은 행, 조항 단위 이진(위반 지목 여부), 5,150건.

### 7-15. 시드 20개 최종 판정 — FB-Check 필터로 학습하면 외부 성능이 좋아지나 (사전 등록, 2026-10-09 — 결과를 보기 전에 적음)

### 7-17. FB-Check v2 — 버리지 말고 확신도로 학습 (사전 등록, 2026-10-12 — 결과를 보기 전에 적음)

**왜 (진단, 운영 FB-Check 데이터 4,465건):** NOISE 1,113건 중 **98%가 위반 라벨**이고, FB-Check는 위반 라벨 전체의 **43.9%를 버린다.**
버린 위반 라벨의 **79.5%는 verify도 위반으로 봤다**(등급·조만 불일치). §7-15·§7-16에서 반복된 "필터 모델이 보수적·조 F1 낮음"은 이것으로 설명된다.
**§7-9·§7-15·§7-16 세 번의 하류 미판정을 본 뒤 세운 가설임을 논문에 명시한다. 이번이 하류 학습 마지막 시도다.**

**FB-Check v2 규칙 (고정):** F = forward 조, V = verify 조.
- 버림: F가 있는데 근거 문구가 원문에 없음 · F가 있는데 V가 비어 있음(검증이 위반 아님)
- 나머지 전부 학습. 조별 목표값: **F∩V → 1.0 · 한쪽만(F△V) → 0.5 · 둘 다 아님 → 0**
- 학습 4,217건(A 4,465에서 248건 제외), 0.5 목표가 있는 레코드 978건. dev(임계값·체크포인트)는 A와 같이 forward 정답(이진)을 쓴다. pos_weight는 forward 빈도(A와 같다)

**팔:** S = v2 · A = 필터 없음(forward, 기존 3시드 + 새 7시드) · D = 기존 FB-Check(20시드 중 같은 10시드). 시드 42, 7, 123, 11, 22, 33, 44, 55, 66, 77.

**보조 판정: S − D AUROC** CI 하한 > 0 → "v2가 기존 FB-Check보다 낫다".
**보고(판정 아님):** 조 F1 · 오경보@재현80 · 배포 재현/오경보, A − D.
**미판정이면 하류 학습 축을 최종 종료한다.** 시드는 더 늘리지 않는다.

### 7-18. 인과 확인 — 맞는 위반 사례를 버린 것이 원인인가 (사전 등록, 2026-10-12 — 결과를 보기 전에 적음)

**왜:** §7-17 기전 분석에서 FB-Check는 판별 오류를 더 거르지만(+15.7%p) 학습 데이터에서 맞을 가능성이 높은 공정위 위반 사례 869건도 버린다.
"맞는 위반 사례 손실이 기존 FB-Check(D)의 조 식별 저하·보수화의 원인"인지 학습으로 확인한다.
**하류 학습 축은 §7-17에서 종료를 선언했으나, 기전 분석 후 사용자 요청으로 인과 확인 1회를 다시 연다 — 논문에 경위를 밝힌다.**

**팔 DS (고정):** A(forward 전체 4,465)에서 **표준계약서 출처의 FB-Check NOISE 228건만** 뺀다. 공정위 조항은 NOISE여도 전부 남긴다. 4,237건, forward 라벨.
(출처 가정: 표준계약서 ≈ 적법 → 그 위반 라벨은 오류일 가능성이 높다. 학습 데이터는 출처를 알므로 실제로 쓸 수 있는 규칙이다)
비교: D(기존 FB-Check) · A(필터 없음), 같은 10시드(42, 7, 123, 11, 22, 33, 44, 55, 66, 77). 평가: AI Hub 전체, §7-9와 같은 `contrast`.

**주 판정 2개 (본페로니: 각각 97.5% CI):**
- **H1 (원인 확인): DS − D 조 F1** CI 하한 > 0 → "맞는 위반 사례 손실이 조 식별 저하의 원인"
- **H2 (실용 규칙): DS − A AUROC** CI 하한 > 0 → "출처 한정 FB-Check가 필터 없음보다 낫다"
**보고:** DS − D 배포 재현·오경보(보수화가 풀리는지), DS − D AUROC, DS − A 조 F1.
시드는 늘리지 않는다. 이 실험 후 하류 학습 축은 다시 열지 않는다.

**결과 (2026-10-12, `aihub_seeds20.py --ds` → `aihub_eval.py --mode ds` → `data/eval/model/aihub_eval_ds.json`) — H1·H2 모두 미판정**

- **H2 미판정:** 출처 한정 FB-Check도 필터 없음과 구분되지 않는다

- **하류 학습 축 최종 종료(5번 시도: §7-9·7-15·7-16·7-17·7-18).** 다시 열지 않는다

  FB-Check는 오경보 비율을 3.4%p 낮추는 대신 위반 사례를 버려 **놓친 위반 비율을 7.1%p 높였다** — 오류의 종류가 바뀌었을 뿐 학습 데이터 전체 오류가 줄지 않았다
- 따라서 이 데이터에서 하류 가설의 **전제 자체가 성립하지 않았다.** 하류 null은 "FB-Check가 실패"가 아니라 "라벨 수준 정밀도 개선이 학습 데이터 수준 오류 감소로 이어지지 않는 구조"로 서술한다(출처 가정에 기댄 추정치임을 밝힌다)


### 7-19. 누락 검사(Recall-Check) 가능성 확인 — 데이터 수준 오류 (사전 등록, 2026-10-12 — 결과를 보기 전에 적음, 학습·API 0)

**왜:** FB-Check는 붙은 라벨만 검사해 놓친 위반(AI Hub 위반의 33.7%)을 8.9%만 되살린다(§7-17). **다른 계열 모델(KoELECTRA 인코더)**로 빈 라벨을 교차 확인하면 놓친 위반을 찾을 수 있는지 본다.
평가는 **학습 효과가 아니라 데이터 수준 오류**로만 한다(하류 축은 §7-18에서 종료).

**데이터:** §7-14 행(Qwen forward + FB-Check) 중 **AI Hub 평가 절반 파일**(`aihub_split.json` train_files 밖, 2,571행 · 위반 1,245) — 인코더가 학습에 쓰지 않은 파일이다.
**인코더 (고정):** 배포 모델 `article_v3`와 같은 CN 시드 7 + 회사 약관 임계값(CNA_s7) — 예측 캐시 `CNA_s7.npz`. 조 하나라도 p ≥ 임계값이면 "위반".
**파이프라인:**
- P0 = Qwen forward 라벨 그대로 (전부 유지)
- P1 = FB-Check (CLEAN만 유지, NOISE는 데이터에서 제외)
- **P2 = P1 + 누락 검사**: P1이 유지한 행 중 **forward 빈 라벨인데 인코더가 위반**이면 위반 라벨로 바꾼다(조는 인코더 예측)
**데이터 수준 오류 (이진, 조항 단위 정답):** 유지된 행 중 (공정 조항에 위반 라벨 + 위반 조항에 빈 라벨) 비율. 오경보율·놓친 위반율도 따로.

**주 판정:** P2 − P1 데이터 수준 오류율, 파일 군집 부트스트랩(5,000회) 95% CI 상한 < 0 → "누락 검사가 데이터 오류를 줄인다".
**보조 판정 (교차 확인이 무작위 이상인가):** 빈 라벨 행 중 인코더가 위반이라 한 것의 실제 위반 비율(정밀도) − 빈 라벨 행 전체의 위반 비율(기저율), CI 하한 > 0.
**보고:** 되살린 놓친 위반 비율, 새로 생긴 오경보 수, 다른 시드(42·123) 결과, P0 대비.
**한계:** 평가 집합은 위반:공정 1:1로 맞춘 것이라 오류율 절대값은 실제 분포와 다르다(상대 비교만). LLM 라벨러가 GPT가 아니라 Qwen이다.

### 7-20. 누락 검사 ② — 운영 GPT-4o 학습 데이터 (사전 등록, 2026-10-12 — 결과를 보기 전에 적음, API 0)

운영 데이터에는 조항 단위 정답이 없어 **출처 가정**(공정위 조항 ≈ 위반, 표준계약서 ≈ 적법)으로 채점한다.

**교차 확인 모델 (자기 데이터 순환 방지 — 문서 단위 5겹 교차):** A 4,465건을 문서 단위로 5겹(시드 42). 겹마다 **나머지 4겹의 FB-Check CLEAN 레코드(forward 라벨)**로 KoELECTRA를 학습(D 팔과 같은 설정)하고, 빼 둔 겹의 전 레코드를 예측(dev 임계값, 조 하나라도 넘으면 "위반"). 가중치는 예측 후 삭제.
**누락 검사:** FB-Check CLEAN이면서 forward 빈 라벨인 레코드 중 인코더가 위반이라 한 것을 "놓친 위반 후보"로 표시.

**⚠ 출처 지름길 교란:** 라벨이 출처와 강하게 얽혀 있어(TF-IDF가 출처를 96.9% 맞힘) 인코더가 **내용이 아니라 공정위 문체**를 보고 표시할 수 있다. 그러면 출처 채점에서 정밀도가 부풀려진다.
**대조군 (문체만 보는 기준선):** 같은 겹 구조로 학습한 **TF-IDF 출처 판별기**(공정위 vs 표준계약서)가 빈 라벨 중 "공정위일 확률" 상위 **같은 수**를 표시한 것.

**주 판정:** 빈 라벨 중 인코더 표시분의 공정위 비율(출처 정밀도) **− 문체 기준선 표시분의 공정위 비율**, 문서 군집 부트스트랩 95% CI 하한 > 0 → "인코더가 문체 이상의 내용 신호로 놓친 위반을 찾는다".
**보조 (기술):** 인코더 표시분 공정위 비율 − 빈 라벨 전체 공정위 비율(기저율), CI 하한 > 0. 데이터 수준 추정 오류(표준계약서 위반 라벨 + 공정위 빈 라벨)의 P1 → P2 변화.
**해석 규칙:** 주 판정이 미판정이면 보조가 통과해도 "출처 문체로 설명될 수 있음"으로만 쓴다. 학습 효과는 재지 않는다(하류 축 종료).

- **인용 위반 급증의 원인(사후 진단): 두 번째 프롬프트 결함.** v2에서 "조 번호"라고 쓰자 모델이 `"6"`처럼 숫자만 적었다. 위반 160건 **전부** 형식 차이였고 제공 외 조를 인용한 경우는 **0건**이다(A1은 172건 중 2건). 숫자를 "제N조"로 정규화하면 위반율은 **A0 0.0%, A1 1.1%**로 기준(≤2%) 안이다. 설명 본문이 제공 외 조를 언급한 경우는 두 팔 모두 0건
- 이 정규화는 결과를 본 뒤 정한 **탐색적 재계산**이다. 사전 등록 지표(엄격 비교)로는 미달이며 그대로 보고한다. 검증 코드는 정규화하도록 고쳤다(`normalize_cited`, 안 고치면 켰을 때 출력의 89%가 폐기된다)
- **진짜 남은 실패는 근거 문구 원문 일치율(84.9 / 87.2%).** 프롬프트로 "그대로 복사"를 강하게 요구해도 v1(83.8%)과 거의 같다 → 생성 모델이 문구를 줄임표·따옴표 변경 등으로 다듬는 성질이 프롬프트로 안 고쳐진다
- **판례(A1)는 근거 문구 일치율을 몇 %p 올렸으나 구간이 겹친다**(87.2 [82.7, 91.6] 대 84.9 [79.9, 89.9]). 판례 효과로 쓰지 않는다. 판례 검색 1건이 NUL 문자로 빈 결과였다

**다음 단계(제안, 미실행):** 기준 ②를 프롬프트가 아니라 **구조로** 해결한다 — 모델에게 문구를 쓰게 하지 않고 조항을 문장 단위로 나눠 번호를 붙인 뒤 "가장 핵심적인 문장 번호"를 고르게 하면 근거 문구가 원문 그대로임이 구성상 보장된다. 이 변경은 새 설계이므로 v3로 따로 사전 등록하고 같은 기준으로 재평가한다. 프롬프트 수정을 또 반복하면 같은 평가셋을 세 번째 쓰는 것이라 피한다. 어댑터(LoRA)는 v3도 미달할 때만 간다.

| B5 | 문구 변형에 배포 모델이 약하다 | Qwen 재작성 위반 조항 재현 78.5 → 57.8% | 변형 의미 보존은 자동 검사로만 확인 | §7 P2-⑤ |

### D. 철회·반증 (한계 절)

- 하류 학습 "C가 오경보 −23.8%p 우위" — 철회(제13조 헤드 인공물)
- "KoELECTRA가 GPT와 성능 동등" — 조 식별은 GPT 우위로 수정
- "KoELECTRA만 단순 기준선을 이긴다" — TF-IDF와 조 F1 구분 안 됨
- RoBERTa 교체·말투 증강 — 기존 시험셋 개선이 처음 보는 문서에서 재현 안 됨(§7-3)
- 한 임계값으로 회사 약관과 표준계약서를 동시에 맞출 수 없다(§7-10·7-11) → A3의 라우팅으로 해결

### 한계 (논문에 그대로)

- 사람 전문가 라벨이 없다. 조항 단위 정답은 공정위 gold 255건뿐이다
- 라우팅(A3)의 기준 맞춤과 평가가 같은 출처(AI Hub 반분)다 — 실제 서비스 입력 정답이 없어 실사용 오경보는 직접 재지 못했다
- GPT 반복은 4회(사전 등록 5회에서 이탈)
- 요건 기반 검증은 gold 1회 실행이고 gold는 그 실험에서 소진됐다

## 9. 한계 (논문에 그대로 쓴다)

- 사람 전문가 라벨이 없다. FTC 의결서는 위반 사건만 담고, 음성은 "표준계약서는 적법하다"는 출처 가정에 기댄다. 평가자 간 일치도(κ)는 측정하지 않았다
- 필터 비교 모집단(2,305건)은 사건 단위 근거를 조항마다 복제한 준거다. 최적 상수가 54.4%로 모든 라벨러를 이기므로 절대 F1은 해석하지 않고, 문서 층화 상대 비교만 주장한다
- 오경보는 구간으로만 보고한다(2.8~12.1%; 옛 하한 2.3%는 재현 불가라 폐기, reported_numbers E5). 하류 비교의 홀드아웃은 12문서 300조항이라 MDE가 3~6%p다
- 조 F1은 gold 255로 판정할 수 없다(필요 n≈1,296). 모델 개선 주장은 조항 단위에 한정한다
- 실제 기업 약관 99건에서의 행동 변화는 정답이 없어 채점하지 못했다
- AI Hub 전문가 라벨은 공정위 의결서 가공본이라 gold와 출처가 같다. 텍스트 누수는 제거했지만 같은 규제기관의 판정 경향을 공유한다
