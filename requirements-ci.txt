# requirements-ci.txt
# CI(단위 테스트)용 의존성. API 서빙 공통 패키지는 requirements.txt에서 `-r`로
# 상속받고, 여기서는 테스트 도구만 추가한다.
#
# requirements-dev.txt 전체(playwright, bertopic, umap-learn, hdbscan, top2vec,
# contextualized-topic-models, konlpy 등 데이터 수집·토픽모델링 파이프라인용)를
# 그대로 설치하면 CI가 몇 분씩 걸리고 네이티브 빌드(Java/mecab 등)까지 필요해진다.
# `pytest -m "not integration"`이 실제로 import하는 건 API 서빙 경로
# (backend/api, backend/agents, backend/db)뿐이라 그 부분만 추린다.
#
# backend/agents/judgment_agent.py가 KoELECTRA 추론에 torch+transformers를
# 모듈 최상단에서 import하므로 이 둘은 무거워도 뺄 수 없다.
#
# requirements.txt(공통 API 의존성, sentence-transformers 포함)를 바꾸면 ci/dev
# 전부에 자동 반영된다 — 이 파일엔 pytest 계열 외에는 아무것도 추가하지 말 것.
# CI 테스트는 lifespan을 안 태우니 sentence-transformers를 실제로 쓰진 않지만,
# requirements.txt가 곧 "서버가 기동 가능한 최소 세트"라 여기서 따로 뺄 수 없다.

-r requirements.txt
